The product

Perspective

Portability you can run

“Pluggable backends” is the most over-claimed phrase in infrastructure, so we made ours falsifiable. One event-log surface, four independent implementations, and a conformance suite that every one of them passes.

Compiling the suite proves the API matches. Passing it proves the behaviour does. Records serialise to identical bytes and merkle roots agree at every size, so a proof issued by one backend verifies under another—which is also what makes a migration checkable rather than hopeful.

Perspective

Speed is a distraction

Teams spend months debating Rust vs Java vs TypeScript based on benchmarks that vanish behind a single database query. We built the same 13-entity federated API in all three languages, against the same MongoDB infrastructure. Under load, they converge.

The difference between “0.7ms” and “1.8ms” is undetectable to any human or frontend. The real performance lever is infrastructure—indexing, connection pooling, sharding—not language choice. The right question isn't “which language is fastest?” It's “which language lets this team ship reliable software fastest?”

Perspective

From laptop to production

The same code runs everywhere. No rewrites between environments, no backend-specific logic leaking into your schemas, no “works on my machine.”

Your laptop

merkql · an embedded log, no server

A directory on disk and cargo run. No container, no cluster, nothing to install. One process writes it, which on a laptop is every process there is.

Serverless

merk-aws · ~11,700 events/sec per partition

Compare-and-swap appends to S3 Express One Zone, so concurrent Lambdas serialise against the store itself—no broker, no lease, no coordinator. Measured in region at 7.4ms per flush. No VPC, no NAT gateway, and genuinely nothing running when idle.

Your database

merkpgql · PostgreSQL you already run

The log becomes a table rather than new infrastructure—no new backup policy, monitoring or sign-off. Writers queue on a row lock instead of colliding, events are queryable by key, and an append can share a transaction with your domain write.

Enterprise

Kafka · when the log never goes quiet

A broker earns its operational cost when throughput is sustained rather than bursty. Same API, same schemas, same clients. We will tell you when you have reached that point, and it is further away than most people assume.

You promote your environment, not rewrite your code.

The toolkit

Tools we build and use

What is published is under BSL 1.1—free for non-production use, commercial license for production. The cloud and database backends are commercial and not public; merkql, the log itself, deliberately is.

Service

meshql-ts

TypeScript · The OG

The original MeshQL. Schema-driven REST + GraphQL APIs with Express, federation resolvers, four database backends. Where the model was proven.

Source

meshql-java

Java 21 · Enterprise

The same model in Java. Jetty 12, virtual threads, PostgreSQL, MongoDB, SQLite, ksqlDB. Better performance at the cost of more memory—a natural fit for virtual infrastructure.

Documentation Source

meshql-rs

Rust · Deploy anywhere

The same model in Rust. Pluggable backends, sub-millisecond internals, a 3.8MB binary. Lambda, edge, embedded. The hard bits are done.

Source

Storage

merkql

Rust · Embedded event log

Kafka semantics backed by a merkle tree. Topics, partitions, consumer groups, and cryptographic inclusion proofs—without the cluster. The storage engine that makes “no server required” possible. Single-writer by design, and it says so plainly when you outgrow it.

Documentation Source

merk-aws

Rust · S3 Express One Zone

The same log on object storage. Compare-and-swap appends mean concurrent producers serialise against S3 itself, so many Lambdas can write one partition with nothing coordinating them and nothing running between requests.

merk-azure

Rust · Azure append blobs

The same log again, on native append blobs with server-enforced sealing. No Azure SDK—a handful of REST calls and a signer—so an Azure Functions cold start stays small.

merkpgql

Rust · PostgreSQL

The log in your database and in your transactions. Writers queue on a row lock rather than colliding, events are queryable by key, and an append can share a commit with the domain write that caused it—which is the outbox problem not existing rather than being solved.
